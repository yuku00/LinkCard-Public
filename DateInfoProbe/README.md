# DateInfoProbe 0.3

SpringBoard-only, bounded diagnostic. It never reads user text, touch coordinates or URLs, never sends network requests, and does not hook global touch delivery. It inspects private recognizer target layout; inability to inspect or match means **unknown**, not absence of DateInfo behavior. The probe attaches a parallel counter only after matching DateInfo class, selector, image and ABI. It removes its targets at the end. The extra target and scans can affect timing or target iteration order.

## Start a single session

1. Install the RootHide package, respring, and unlock. Existing `/var/mobile/Library/Logs/DateInfoProbe-v03.json` prevents the new run from starting; first move or delete only your own earlier diagnostic output if you want another run. Never overwrite an unrelated file.
2. Within 10 minutes of injection, use Filza to create `/var/mobile/Library/Logs/DateInfoProbe-v03.start` as a **new, zero-byte regular file**, owned by mobile (UID 501), with a modification time later than injection. If an old start file exists, first move or delete it only if it is your own earlier trigger. The probe does not delete the trigger. If Filza creates files as root, set owner to mobile. Symlinks and non-empty files are rejected.
3. Switch from Filza back to the home screen immediately. The trigger is checked every 2 seconds; after detection there is a 20-second delay, then a 90-second sampling interval. Exercise the relevant DateInfo clock tap during that interval. This is a file-triggered session, not an unlock trigger or a button.
4. After about 115 seconds from creating the trigger, open `/var/mobile/Library/Logs/DateInfoProbe-v03.json` in Filza. An empty, absent or invalid file means the session did not complete; do not treat it as a zero result. A `completed` record includes a unique UUID, UTC timestamps, per-scan window/foreground counts and stage observation deltas, and final callback counts and removal attempts. The old `DateInfoProbe.json` is never read or written. This report is not automatically uploaded.
5. Stop future observation by uninstalling the diagnostic package and respringing; a respring during a session aborts it and may leave an empty or incomplete file. Save only the report you intend to share. The output is created exclusively and existing files are never replaced.

The probe samples main-thread view trees in small batches, at most one scan every 5 seconds, with a 10,000-view scan bound and at most 20 scan records. Long scans may take more than 5 seconds. Scans and callbacks are not a proof that the original action or presentation executed. Private UIKit layouts differ by iOS version, and DateInfo may not have loaded when the trigger is used. The package has not been validated on the user's physical device.
