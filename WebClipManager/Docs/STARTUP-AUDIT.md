# Startup and AppIcon audit (build 2)

## Confirmed defects fixed

The IPA from Actions run 41293692375 contains no AppIcon PNG, Assets.car, CFBundleIcons or CFBundleIcons~ipad. `python3 Tools/verify_ipa.py OLD.ipa` fails with `Missing compiled asset catalog`. Add the asset catalog to XcodeGen resources and select AppIcon so actool generates both device-family icon declarations. Original geometric browser/globe/bookmark artwork is generated by Tools/generate_icon.py (Pillow), under the project MIT license; no downloaded imagery or user data. Thirteen opaque RGB PNG sizes cover iPhone, iPad and marketing slots.

The old generated plist also says version 1.0 although MARKETING_VERSION is 0.1.0. Explicit build-variable substitutions now keep plist version/build consistent (0.1.0 / 2). This is not a crash fix.

## Launch investigation: not yet a diagnosed crash

User reports immediate exit before seeing UI and has no IPS log. No device process trace is available. Do not interpret icon repair, successful compilation or static checks as proof that the reported crash is fixed.

The old executable is arm64, MH_EXECUTE, platform iOS (not Simulator), LC_BUILD_VERSION minimum 16.0 and SDK 18.5 (Xcode 16.4). An SDK newer than the OS is not itself a deployment error. All load commands refer to system frameworks/libraries; there is no missing third-party @rpath library in this package. Weak Swift overlay loads are distinguished from required libraries. Presence of a system library name does not prove every imported symbol exists on iOS 16.6.

Both old ldid CodeDirectories (SHA-1 and SHA-256) verify all 266 code pages and the XML/DER entitlement blob digests. XML entitlements equal the sole configured `com.apple.private.security.no-sandbox=true`. No banned debugger/dynamic-codesigning/skip-library-validation entitlement is present. Hash integrity is not verification of the installed app's CoreTrust trust or LaunchServices registration.

TrollStore's official README explicitly recommends `ldid -S<entitlements> <binary>` and states that it re-signs the app on install. It also documents that apps registered as User after an icon cache refresh may not launch until persistence-helper registration is refreshed. This is a possible installation-state cause, NOT an observation about this device. No speculative platform-application, JIT or debugger entitlements were added.

Entry path: SwiftUI App -> RootView -> Model/Repository; initial ManagerView task scans WebClips and catches thrown errors. Notes reads require user confirmation, so no evidence supports attributing this pre-UI exit to Notes. No real Notes or WebClip data was accessed during this audit. Deletion remains disabled.
